# release-notify

릴리즈 노트에 새 버전이 push 되면 Slack 채널로 알림을 보내는 공용 GitHub Actions 워크플로.

sym804 계정의 여러 레포가 이 워크플로 하나를 불러 쓴다. 알림 형식을 고칠 때는 이 레포만 고치면 된다.

## 동작

- 레포마다 `.github/workflows/release-notify.yml` 이 있고, 릴리즈 노트 파일이 바뀐 push 에서만 실행된다.
- `notify.py` 가 push 이전과 이후의 릴리즈 노트에서 릴리즈 후보를 뽑아 비교한다. 후보는 두 가지다.
  - `##`/`###` 제목 중 버전 번호(`1.6.10.5`, `v0.8.23`)나 날짜(`2026-07-19`)가 든 것. 릴리즈 제목 아래의 `###` 는 소제목으로 본다.
  - 첫 칸 머리글이 `버전` 인 표에서 첫 칸이 버전인 행. 제목 없이 표에만 적는 레포(suika-clone)용이다.
- 같은 버전(버전이 없으면 날짜)의 절끼리 짝을 짓는다. 제목이 그대로면 기존 절이고, 제목이 바뀌었어도 본문이 60% 이상 같으면 제목만 고친 것으로 본다. 이슈 번호 교정, 이름표 변경, 기호 치환은 알리지 않는다.
- 알림에는 레포 이름, 릴리즈 제목, 요약 최대 5줄, 커밋 링크가 들어간다. 요약은 `변경` / `수정` / `개선` / `Changed` / `Fixed` 같은 소제목 아래 항목을 쓴다. 그런 소제목이 없으면 `검증` / `원인` / `배경` / `남은 것` 등을 뺀 첫 항목을 쓰고, 불릿이 없으면 첫 문단 한 줄을 쓴다.
- 릴리즈 노트 파일을 처음 만든 push 는 맨 위 릴리즈 하나만 알린다.

## 설치

필요한 것: `gh` 로그인, `~/.slack_release_webhook` 에 Slack Incoming Webhook 주소 한 줄.

```bash
python install.py            # 대상 레포와 릴리즈 노트 경로 조회만
python install.py --apply    # 비밀값 등록 + 워크플로 커밋
```

- 릴리즈 노트가 없는 레포는 건너뛴다.
- 워크플로는 GitHub API 로 원격에 바로 커밋한다. 로컬 클론은 다음에 `git pull` 하면 된다.
- 워크플로의 `paths` 에는 그 레포의 실제 릴리즈 노트 경로가 들어간다. 릴리즈 노트를 새로 만들거나 옮기면 `--apply` 를 다시 돌린다.
- 같은 이름의 워크플로가 이미 있고 이 설치기가 쓴 것이 아니면 건너뛴다. 덮어쓰려면 `--force`.

웹훅을 새로 발급했으면 파일을 바꾸고 비밀값만 다시 등록한다.

```bash
python install.py --apply --secrets-only
```

## 버전 고정을 하지 않는 이유

호출 쪽은 `@main` 을 부른다. 이 레포에 push 할 수 있는 사람이 소유자 한 명뿐이고, 태그나 커밋 해시로 고정하면 알림 형식을 고칠 때마다 11개 레포를 다시 커밋해야 한다. 협업자가 생기면 태그 고정으로 바꾼다.

## 한계

- 알림은 기본 브랜치 push 에서만 간다.
- 웹훅 비밀값이 비어 있으면 워크플로가 실패로 끝난다. 알림이 안 오는 이유를 Actions 탭에서 바로 볼 수 있게 하려는 것이다.
- 제목에 버전도 날짜도 없는 릴리즈는 잡지 못한다.
- 버전 표기 자체를 바꾸면(`0.2.0` 을 `0.2.0.0` 으로) 새 릴리즈로 한 번 알린다.
- 제목과 본문을 한 push 에서 크게 함께 고치면 새 릴리즈로 본다.
- 표는 첫 칸 머리글이 `버전` 인 것만 본다. 다른 표의 버전 칸 변경은 잡지 못한다.
- 릴리즈 노트 파일 이름을 바꾸면 새 파일로 보고 맨 위 릴리즈를 한 번 다시 알린다.
- 옛 `###` 를 `##` 로 올리면서 본문도 고치면(앞부분이 달라지면) 새 릴리즈로 본다.
- `---` 구분선 없이 이어진 절에서 하위 `###` 절을 `##` 로 떼어 내면, 본문이 줄어든 상위 절이 한 번 더 알려질 수 있다.
- 단계를 잘못 적은 새 릴리즈(`##` 릴리즈 안의 `### 1.2.1 (날짜)`)는 상위 절의 본문으로 읽혀 알리지 않는다. 이것은 release-lint 훅이 커밋 단계에서 막는다. 날짜가 없는 `### 1.2.1` 은 훅도 못 막고 알림도 없다. 다음 push 에서 `##` 로 올리면 그때 알린다.
- 4,000자가 넘는 본문은 앞뒤 2,000자씩만 견준다. 같은 열쇠의 절에서 가운데만 통째로 바꾸면 제목만 고친 것으로 본다.
